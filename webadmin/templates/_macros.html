{# Field-rendering helpers. Every option's explanation lives in its WTForms `description`, and these macros turn it into a tooltip on the field row. Keeping the rendering here rather than in each template means a field picks up its tooltip from having a description, with nothing to remember at the call site. The whole row is the hover target, not a small "?" marker: aiming at a one-em circle to read a sentence is more work than the sentence is worth. The row also covers the keyboard case for free -- focusing the input is :focus-within on the row. #} {# The tooltip body. Must be a DIRECT child of .field: the CSS shows `.field:hover > .tip`, so that a row containing several individually documented controls (the per-slot video options) does not throw all of their tooltips up at once. #} {% macro tip(field) -%} {%- if field.description -%} {{ field.description }} {%- endif -%} {%- endmacro %} {# Label-then-input, for text/number/password/select fields. #} {% macro row(field) -%}
{{ field.label }}: {{ field(aria_describedby=field.id ~ '-tip', **kwargs) }}{{ tip(field) }}
{%- endmacro %} {# Checkbox-then-label, for BooleanFields. #} {% macro check(field) -%}
{{ field(aria_describedby=field.id ~ '-tip', **kwargs) }} {{ field.label }}{{ tip(field) }}
{%- endmacro %} {# Action icons for the log listings. Inline SVG rather than an icon font or emoji: it needs no external request (the pages are served under a strict policy and must be self-contained), it inherits colour from the surrounding text via currentColor, and it renders identically everywhere -- emoji glyphs for these do not, and a bin in particular is missing on plenty of systems. Every call site pairs one with a title and aria-label. An icon alone is a guess for a sighted user and nothing at all for a screen reader. #} {% macro icon(name) -%} {%- if name == 'play' -%} {%- elif name == 'download' -%} {%- elif name == 'trash' -%} {%- endif -%} {%- endmacro %}
